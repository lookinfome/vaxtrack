1. HIGH-LEVEL ARCHITECTURE DIAGRAM
================================================================================

  +------------------+
  |   HTTP Client    |  (Postman / Frontend / Mobile)
  +--------+---------+
           |
           | HTTPS
           v
  +------------------+       +---------------------+
  |  ASP.NET Core    |       |  SQL Server          |
  |  Web API         |<----->|  (VaxtrackDbContext) |
  |  (.NET 10)       |  EF   |                      |
  |                  |  Core |  Tables:             |
  |  Controllers     |       |  - Users             |
  |  Services        |       |  - UserCredentials   |
  |  Repositories    |       |  - Hospitals         |
  |                  |       |  - Bookings          |
  +------------------+       |  - UserRoleMappings  |
           |                 |  - RevokedTokens     |
           | Logs            |  - PasswordReset     |
           v                 |    Tokens            |
  +------------------+       +---------------------+
  |  Serilog Logs    |
  |  (File + Console)|
  +------------------+

Authentication flow:
  Client ---[JWT Bearer token in header]---> API
  API reads token, validates signature + expiry + JTI-blacklist check
  If valid: Principal populated, controller executes
  If invalid: 401 Unauthorized returned before hitting controller

================================================================================

  |  UseAuthorization  |  <-- enforces [Authorize] and [Authorize(Roles=...)]
  +--------+-----------+

  +---------------------------+
  |     CONTROLLERS           |  (one per domain, DI injected)

  +--------+------------------+
           |
           v
  +---------------------------+
  |     SERVICE LAYER         |  (business logic, ownership checks, mapping)
  |  AuthService              |

  |  HospitalService          |
  |  BookingService           |
  |  UserRoleMappingService   |
  |  UtilityService           |
  +--------+------------------+
           |
           v
  +---------------------------+
  |     REPOSITORY LAYER      |  (data access via EF Core, no business logic)
  |  UserRepository           |
  |  UserCredentialsRepository|
  |  HospitalRepository       |
  |  BookingRepository        |
  |  UserRoleMappingRepository|
  |  TokenBlacklistRepository |
  |  PasswordResetTokenRepo.  |
  +--------+------------------+
           |
           v
  +---------------------------+
  |  VaxtrackDbContext (EF)   |
  |  SQL Server               |
  +---------------------------+

Key design principles:
  - Each layer only talks to the layer directly below it.
  - Services own all business logic; repositories own only EF queries.
  - Interfaces are defined for every service and repository (DI contracts).
  - UnauthorizedAccessException propagates from service → controller → Forbid().
  - Generic exceptions propagate from service → controller → 500.

4. REQUEST PIPELINE (every HTTP request)
================================================================================

  Client sends request with: Authorization: Bearer <jwt>
           |
           v
  [UseAuthentication]
    - Validate JWT signature using HMAC-SHA256 + appsettings Key
    - Validate issuer, audience, token lifetime
    - ClockSkew = TimeSpan.Zero (no tolerance)
    - If invalid: return 401 immediately
           |
           v
  [OnTokenValidated event]
    - Extract JTI claim from Principal
    - Query RevokedTokens table: IsRevokedAsync(jti)
    - If revoked: context.Fail("Token has been revoked") → 401
           |
           v
  [UseAuthorization]
    - Check [Authorize] → must be authenticated (done above)
    - Check [Authorize(Roles="admin")] → token's "role" claim must be "admin"
    - If fails: 403 Forbidden
           |
           v
  [Controller Action]
    - Extract CallerUserUid = User.FindFirst("sub")?.Value
    - Extract CallerIsAdmin  = User.IsInRole("admin")
    - Call service method with these values
           |
           v
  [Service Layer]
    - Business logic, ownership checks
    - UnauthorizedAccessException → propagates up
    - Other exceptions → propagates up
           |
           v
  [Controller catches]
    - UnauthorizedAccessException → return Forbid() (403)
    - Exception → log + return StatusCode(500)
           |
           v
  [Response sent to client]

5. OPERATIONAL FLOW: USER REGISTRATION
================================================================================

  POST /User/CreateUserAsync  (AllowAnonymous)

  Client
    |-- POST {FirstName, LastName, Birthdate, Gender, Phone, Address,
    |         PinCode, Email, Password}
    v
  UserController.CreateUserAsync
    |-- call UserService.CreateUserAsync(dto)
    v
  UserService.CreateUserAsync
    |-- [1] Validate Birthdate < UtcNow
    |-- [2] GetCredentialsByEmailAsync(email)
    |        IF found → throw "email already in use"
    |-- [3] UtilityService.GenerateGuidAsync()     → UserUid
    |-- [4] UtilityService.GenerateUniqueIdAsync() → UserId
    |-- [5] UtilityService.CalculateAgeAsync()     → UserAge
    |-- [6] UserRepository.CreateUserAsync(UserModel)
    |-- [7] BCrypt.HashPassword(Password)
    |-- [8] UserCredentialsRepository.CreateCredentialsAsync(credentials)
    |-- return CreateUserResponseDto
    v
  Controller returns 201 Created with location header pointing to
  GetUserProfileDataAsync/{userId}

6. OPERATIONAL FLOW: USER LOGIN
================================================================================

  POST /Auth/LoginAsync  (AllowAnonymous)

  Client
    |-- POST {Email, Password}
    v
  AuthController.LoginAsync
    |-- call AuthService.LoginAsync(dto)
    v
  AuthService.LoginAsync
    |-- [1] UserCredentialsRepository.GetCredentialsByEmailAsync(email)
    |        IF null → throw "invalid email or password"
    |-- [2] BCrypt.Verify(password, hash)
    |        IF false → throw "invalid email or password"
    |-- [3] UserRepository.GetUserDetailsByUserUidAsync(credentials.UserUid)
    |        IF null (soft-deleted) → throw "invalid email or password"
    |-- [4] Set expiry = UtcNow + JwtSettings.ExpiryMinutes
    |-- [5] GenerateJwtToken(user, email, expiry)
    |        Claims: sub=UserUid, email, name,
    |                role="admin"|"user", jti=NewGuid
    |-- return LoginResponseDto {Token, ExpiresAt, UserId, ...}
    v
  Controller returns 200 OK with JWT

7. OPERATIONAL FLOW: USER LOGOUT
================================================================================

  POST /Auth/LogoutAsync  (Authorize)

  Client
    |-- POST  (no body, JWT in header)
    v
  [Pipeline validates JWT, runs OnTokenValidated — token must NOT be revoked]
    v
  AuthController.LogoutAsync
    |-- Extract jti  = User.FindFirst("jti")
    |-- Extract exp  = User.FindFirst("exp") → parse Unix timestamp → DateTime
    |-- call AuthService.LogoutAsync(jti, expiresAt)
    v
  AuthService.LogoutAsync
    |-- Validate jti not empty
    |-- TokenBlacklistRepository.RevokeTokenAsync(jti, expiresAt)
    |     - Insert into RevokedTokens
    |     - Purge expired rows (RevokedAt < UtcNow) opportunistically
    v
  Controller returns 200 { "message": "logged out successfully" }

  Next request with same token:
    OnTokenValidated → IsRevokedAsync(jti) = true → context.Fail() → 401

8. OPERATIONAL FLOW: FORGOT PASSWORD (2-STEP)
================================================================================

  STEP 1 — Request reset token
  POST /Auth/ForgotPasswordAsync  (AllowAnonymous)

  Client
    |-- POST {Email}
    v
  AuthService.ForgotPasswordAsync
    |-- [1] GetCredentialsByEmailAsync(email)
    |        IF null → return generic response (no token, no error hint)
    |-- [2] GetUserDetailsByUserUidAsync(credentials.UserUid)
    |        IF null (deleted) → return generic response
    |-- [3] token = Guid.NewGuid().ToString("N")   (32 hex chars)
    |-- [4] expiresAt = UtcNow + 15 minutes
    |-- [5] PasswordResetTokenRepository.CreateTokenAsync(UserUid, token, expiresAt)
    |-- return ForgotPasswordResponseDto {Message, ResetToken, ExpiresAt}
    v
  Client receives token (in production: sent via email, stripped from response)

  STEP 2 — Submit token + new password
  POST /Auth/ResetForgottenPasswordAsync  (AllowAnonymous)

  Client
    |-- POST {ResetToken, NewPassword}
    v
  AuthService.ResetForgottenPasswordAsync
    |-- [1] GetValidTokenAsync(token)
    |        Query: !IsUsed AND ExpiresAt > UtcNow
    |        IF null → throw "invalid or expired"
    |-- [2] GetCredentialsByUserUidAsync(resetToken.UserUid)
    |        IF null → throw
    |-- [3] GetUserDetailsByUserUidAsync(resetToken.UserUid)
    |        IF null → throw
    |-- [4] MarkTokenAsUsedAsync(resetToken.Id)  ← before hash write (race guard)
    |-- [5] BCrypt.HashPassword(NewPassword)
    |-- [6] UpdatePasswordHashAsync(UserUid, newHash)
    |-- [7] Stamp UserModel.UpdatedAt = UtcNow
    |-- return ResetForgottenPasswordResponseDto {UserId, UpdatedAt}

10. OPERATIONAL FLOW: DELETE USER (CASCADE)
================================================================================

  Admin: DELETE /User/DeleteUserAsync/{userId}
  Self:  DELETE /User/DeleteMyAccountAsync

  [Common cascade path: ExecuteUserDeleteCascadeAsync(userModel)]

  |-- [1] UserRepository.UpdateUserAsync(user with IsDeleted=true, DeletedAt=now)
  |         → User blocked from login immediately (credential lookup excludes deleted)
  |
  |-- [2] BookingService.DeleteBookingsByUserUidAsync(user.UserUid)
  |         → GetAllActiveBookingsByUserUidAsync(userUid)
  |         → For each active booking: DeleteBookingAsync(bookingId)
  |              → Soft-delete booking
  |              → If Dose1 pending: UpdateAvailableSlotsAsync(D1Hospital, +1)
  |              → If Dose2 pending: UpdateAvailableSlotsAsync(D2Hospital, +1)
  |
  |-- [3] UserRoleMappingService.RevokeUserRoleMappingsAsync(user.UserUid)
  |         → RevokeAllMappingsByUserUidAsync(userUid)
  |         → Sets IsActive=false on all mappings for this user
  |
  |-- [4] UserCredentialsRepository.SoftDeleteCredentialsByUserUidAsync(userUid)
  |         → IsDeleted=true, DeletedAt=now (email freed for re-registration)

12. OPERATIONAL FLOW: UPDATE HOSPITAL (with hospital-admin)
================================================================================

  PUT /Hospital/UpdateHospitalAsync  (any authenticated user)

  Caller (hospital-admin OR platform admin)
    |-- PUT {HospitalId, Address, PinCode, Phone, Email}  + JWT
    v
  [Pipeline: validate JWT, not revoked]
    v
  HospitalController.UpdateHospitalAsync
    |-- CallerUserUid = User.FindFirst("sub")
    |-- CallerIsAdmin = User.IsInRole("admin")  → false for hospital-admin
    |-- call HospitalService.UpdateHospitalAsync(dto, CallerUserUid, CallerIsAdmin)
    v
  HospitalService.UpdateHospitalAsync
    |-- [1] GetHospitalByIdAsync(dto.HospitalId) → if null, throw
    |-- [2] IF !callerIsAdmin:
    |         UserRoleMappingRepository.IsUserInRoleAsync(
    |           callerUserUid, "hospital-admin", foundHospital.HospitalId)
    |         Query: UserRoleMappings WHERE UserUid=caller AND RoleTag="hospital-admin"
    |                AND ContextId=hospitalId AND IsActive=true
    |         IF false → throw UnauthorizedAccessException
    |-- [3] Map contact fields
    |-- [4] HospitalRepository.UpdateHospitalAsync(model)
    |-- return UpdateHospitalResponseDto
    v
  200 OK or 403 Forbidden

  NOTE: Same pattern applies to UpdateTotalSlotsAsync and UpdateAvailableSlotsAsync.
  NOTE: UpdateAvailableSlotsAsync is also called internally by BookingService
        with default params (callerIsAdmin=true) to bypass the auth check.

13. OPERATIONAL FLOW: BOOK DOSE 1
================================================================================

  POST /Booking/CreateBookingAsync  (any authenticated user)

  User
    |-- POST {UserUid, Dose1HospitalUid, Dose1RequestedDateTime, Dose1SlotNumber}
    |         + JWT
    v
  BookingController.CreateBookingAsync
    |-- CallerUserUid from JWT
    |-- call BookingService.CreateBookingAsync(dto, CallerUserUid)
    v
  BookingService.CreateBookingAsync
    |-- [1] IF dto.UserUid != callerUserUid → throw UnauthorizedAccessException
    |-- [2] IF Dose1RequestedDateTime <= UtcNow → throw
    |-- [3] BookingRepository.IsBookingExistsAsync(dto.UserUid)
    |        IF true → throw (duplicate booking)
    |-- [4] HospitalService.GetHospitalByIdAsync(Dose1HospitalUid)
    |        IF SlotsAvailable <= 0 → throw
    |-- [5] Build BookingModel (all Dose2 fields null/empty/false)
    |-- [6] BookingRepository.CreateBookingAsync(model)
    |-- [7] HospitalService.UpdateAvailableSlotsAsync(Dose1HospitalUid, -1)
    |        SlotsAvailable decremented by 1
    |-- return CreateBookingResponseDto
    v
  201 Created with location: GetBookingByBookingIdAsync/{bookingId}

14. OPERATIONAL FLOW: BOOK DOSE 2
================================================================================

  PUT /Booking/BookDose2Async  (any authenticated user)

    |-- PUT {BookingId, Dose2HospitalUid, Dose2RequestedDateTime, Dose2SlotNumber}

    |-- [7] IF IsD1RequestCanceled → throw
    |-- [8] GetHospitalByIdAsync(Dose2HospitalUid) → IF SlotsAvailable<=0 → throw
    |-- [9] Set Dose2 fields on booking model
    |-- [10] BookingRepository.UpdateBookingAsync(model)
    |-- [11] HospitalService.UpdateAvailableSlotsAsync(Dose2HospitalUid, -1)
    |-- return BookDose2ResponseDto

15. OPERATIONAL FLOW: APPROVE BOOKING
================================================================================

  PUT /Booking/ApproveBookingsAsync/{bookingId}  (any authenticated user)

  Caller: platform admin OR hospital-admin scoped to the booking's hospital
    |
    v
  BookingController.ApproveBookingsAsync
    |-- CallerUserUid = User.FindFirst("sub")
    |-- CallerIsAdmin = User.IsInRole("admin")
    |-- call BookingService.ApproveBookingsAsync(bookingId, CallerUserUid, CallerIsAdmin)
    v
  BookingService.ApproveBookingsAsync
    |-- [1] GetBookingDetailsByBookingIdAsync(bookingId) → if null, throw
    |-- [2] IF IsVaccinationCompleted → throw (nothing to approve)
    |-- [3] Determine which dose:
    |        approvingDose1 = !IsDose1Completed AND !IsD1RequestCanceled
    |        approvingDose2 = IsDose1Completed AND Dose2HospitalUid not empty
    |                         AND !IsDose2Completed AND !IsD2RequestCanceled
    |-- [4] IF !approvingDose1 AND !approvingDose2 → throw (no pending dose)
    |-- [5] IF !callerIsAdmin:
    |         relevantHospitalId = approvingDose1
    |                              ? Dose1HospitalUid : Dose2HospitalUid
    |         IsUserInRoleAsync(callerUserUid, "hospital-admin", relevantHospitalId)
    |         IF false → throw UnauthorizedAccessException
    |-- [6a] IF approvingDose1:
    |          IsDose1Completed = true
    |          Dose1CompletedDateTime = UtcNow
    |-- [6b] IF approvingDose2:
    |          IsDose2Completed = true
    |          Dose2CompletedDateTime = UtcNow
    |          IsVaccinationCompleted = true
    |          VaccinationCompletedDateTime = UtcNow
    |-- [7] BookingRepository.UpdateBookingAsync(model)
    |-- return BookingProfileDataDto
    v
  200 OK or 403 Forbidden

16. OPERATIONAL FLOW: CANCEL BOOKING
================================================================================

  PUT /Booking/CancelBookingsAsync/{bookingId}  (any authenticated user)

  Caller: booking owner OR platform admin
    |
    v
  BookingService.CancelBookingsAsync
    |-- [1] GetBookingDetailsByBookingIdAsync(bookingId) → if null, throw
    |-- [2] IF !callerIsAdmin AND foundBooking.UserUid != callerUserUid
    |         → throw UnauthorizedAccessException
    |-- [3] IF IsVaccinationCompleted → throw (cannot undo administered vaccine)
    |-- [4] Priority logic:
    |
    |   CASE A: !IsDose1Completed AND !IsD1RequestCanceled
    |     → IsD1RequestCanceled = true
    |     → UpdateBookingAsync
    |     → UpdateAvailableSlotsAsync(Dose1HospitalUid, +1) ← slot restored
    |
    |   CASE B: IsDose1Completed AND Dose2HospitalUid not empty
    |            AND !IsDose2Completed AND !IsD2RequestCanceled
    |     → IsD2RequestCanceled = true
    |     → UpdateBookingAsync
    |     → UpdateAvailableSlotsAsync(Dose2HospitalUid, +1) ← slot restored
    |
    |   ELSE: → throw "no active dose to cancel"
    |
    |-- [5] Re-fetch booking and return BookingProfileDataDto
    v
  200 OK or 403 Forbidden

18. OPERATIONAL FLOW: ASSIGN ROLE
================================================================================

  POST /UserRoleMapping/AssignRoleAsync  (admin only)

  Admin
    |-- POST {UserUid, RoleTag, ContextId}  + admin JWT
    v
  UserRoleMappingController.AssignRoleAsync
    |-- class-level [Authorize(Roles="admin")] enforced by middleware
    |-- call UserRoleMappingService.AssignRoleAsync(dto)
    v
  UserRoleMappingService.AssignRoleAsync
    |-- [1] UserRepository.GetUserDetailsByUserUidAsync(UserUid) → if null, throw
    |-- [2] UserRoleMappingRepository.GetExistingMappingAsync(UserUid, RoleTag, ContextId)
    |
    |   CASE A: Found AND IsActive = true
    |     → throw "already has active role"
    |
    |   CASE B: Found AND IsActive = false  (previously revoked)
    |     → mapping.IsActive = true, UpdatedAt = UtcNow
    |     → UpdateRoleMappingAsync(mapping)
    |     → return reactivated mapping DTO
    |
    |   CASE C: Not found
    |     → new UserRoleMappingModel { UserUid, RoleTag, ContextId, IsActive=true }
    |     → AddRoleMappingAsync(newMapping)
    |     → return new mapping DTO
    v
  201 Created

19. OPERATIONAL FLOW: REVOKE ROLE
================================================================================

  DELETE /UserRoleMapping/RevokeRoleAsync/{mappingId}  (admin only)

  Admin
    |-- DELETE + admin JWT
    v
  UserRoleMappingService.RevokeRoleAsync
    |-- [1] GetRoleMappingByIdAsync(mappingId) → if null, throw
    |-- [2] IF !foundMapping.IsActive → throw "already revoked" (idempotency guard)

  Effect is immediate: next request from that user hits IsUserInRoleAsync,
